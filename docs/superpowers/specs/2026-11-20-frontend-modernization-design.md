# MarketHub frontend modernization design

20 November 2026. The user approved this scope for implementation. See the [implementation plan](../plans/2026-11-20-frontend-modernization.md) and [verification results](../../frontend/RESPONSIVE_TEST_RESULTS.md).

## Approach and constraints

Address verified friction in the existing Blade templates, Tailwind build and vanilla JavaScript. Reuse native HTML, shared navigation, existing permission checks and SweetAlert2. Keep the dashboard hierarchy, status vocabulary and legal-document workflows familiar. A complete shared component redesign would touch each workflow before giving staff a benefit. The proposed batches put keyboard access, recovery and accurate confirmations first, then address performance and smaller consistency issues.

Keep the PHP 7.4.30 compatibility target, Laravel 8.83, existing package versions, public-only Apache routing and Baseline Widely Available. Preserve form payloads and CSRF, permission and ownership checks, market layout coordinates, the exact financial rules and approvals, and original contract files and wording. All fixture writes use an isolated SQLite database and fictional records. Any live rollout, change to browser support requirements or expansion into policy or accounting needs separate direction.

## Batch 1. Shared accessibility, confirmations and recovery

- **Navigation.** Use the existing single permission-filtered sidebar. At narrow widths it is visible in normal document flow before enhancement and remains accessible when the shared script fails. Enable drawer styling and show its trigger only after handlers are ready. When open as a mobile drawer, expose its accessible name and modal semantics and maintain existing Escape, backdrop, close, inert and focus behavior. Clear modal state when closing or crossing the desktop breakpoint. Preserve native disclosures and hide hamburger/compact actions that lack behavior without scripts. Keep desktop sticky and icon-rail behavior. Check cold load for layout shift before settling final enhancement timing.
- **Validation.** Give the common server-error summary a focus target after an invalid redirect. Render keyboard-operable links only for fields whose IDs can be mapped with confidence. Begin with login, tenant registration and staff. Associate field-specific messages using `aria-describedby` alongside existing help IDs, add `aria-invalid` for relevant returned errors, and expand the affected native disclosure before focusing an input. Unmapped form-level errors remain readable in the summary. Avoid guessing nested IDs. Never repopulate passwords or protected ID numbers.
- **Staff forms.** Preserve only the submitted create/edit form's safe values after failure. Scope using the account-specific form identity. Treat that identifier as presentation metadata and continue to authorize from the route and signed-in account. Reopen the appropriate account disclosure on error. Handle pagination through the existing return URL. Verify last-admin/self-disable and password fields alongside safe value restoration.
- **Confirmations.** Fix the contract Terminate/Void prompt mismatch using existing SweetAlert2 and per-button prompt text or separate forms if that is simpler. Preserve the clicked submitter, its action and reason value through confirmation, and focus Cancel first for destructive actions. Cancellation issues no request. Cover keyboard submission and HTML validation with both explicit and default submitters. Do not issue an actual contract during QA.
- **Tables.** Use the existing Sections/Reports named, keyboard-focusable region pattern on audited overflowing tables. Prefer `aria-labelledby` when a useful heading already exists, otherwise use a concise contextual label. Retain the semantic table and all columns, check header associations and the contract action heading. Repair the verified page-level overflow on Sections while retaining its accessibility name suffixes. Keep horizontal scroll inside the region. Avoid a blanket card or sticky-column redesign. Check tables nested in tenant tabs and payment forms for predictable tab order.

**Acceptance.** Synthetic login and staff validation return focus to a usable error and retain allowed values. Nested tenant validation links focus the exact control and keep its description. Mobile authorized navigation and logout work when the script is blocked. Escape and breakpoint changes restore usable focus and clear mobile modal state. At 375/768px and 200% zoom, users can focus and scroll the intended table without losing context. Contract dialogs describe the action, cancel cleanly and submit to the intended existing endpoint.

## Batch 2. Module interactions and consistency

- **Map and stalls.** Keep the coordinate grid and explicit text status. Test two rapid selections under throttling. If reproduced, ensure only the current request updates content, pressed/selected state, focus and `aria-busy`. Separate short live status from the full details panel when needed to avoid reading the whole record twice. Provide an existing authorized Stall-details link for no-script access if the route and permission matrix support that actor. Otherwise keep the visible layout/status and explain the unavailable enhancement without exposing any new record data. Verify section refresh, empty options and failure recovery retain the current authorized and inactive-stall rules.
- **Sections, tenants and business categories.** Reuse existing named table regions, fieldsets, search, tabs and reorder controls. Add distinct accessible names to repeated links where users need to distinguish records. Expose existing required control rules in generic master forms after checking optional and legacy branches. Check nested registration and scoped schedule/policy errors for correct field labels, focus, announcements, preserve/resume and repeat-submit behavior. Use existing business terminology. Preserve automatic calculations, overrides, assignment links and submitted values.
- **Dashboard, rentals, contracts and other screens.** Keep chart value disclosures and status labels. Review narrow-screen spacing, headings, form and status copy and long financial values. Fix a component only where browser or source evidence shows a concrete issue. Rent comparisons must identify automatic, proposed and approved values using text. Maintain report columns, exports, Help authorization and existing contract preview/download authorization. Confirm responsive placement of actions and validation at narrow widths.

**Acceptance.** In the isolated fixture, exercise real login, navigation, tenant and business save/resume, eligible stall and section selection, category filtering, server rental previews, permitted override request and denied-role access. Check simulated preview errors and stale requests. Verify controlled template preview and private download using existing fictional fixtures and retain the original checksum. Compare map coordinates and selected financial controls before and after. Complete payments, assignments, reports, Help and billing regression checks through their existing supported paths.

## Batch 3. Measured loading improvements

- Include the existing deferred Chart.js asset only on Dashboard. Preserve its execution order and verify all five charts with their text equivalents. Compare request count and decoded bytes with browser cache disabled. This supplies a resource-size result. Report any loading time or Core Web Vitals change only with comparable runs.
- Add correctly sized, below-fold lazy loading to allowlisted Help images where repeated browser measurements show meaningful requests or layout shifts. Keep the first visible image priority, Markdown escaping and authenticated paths. Use intrinsic dimensions from existing image metadata or the already allowlisted local assets.
- Trace the legacy-rate relation lookup and measure it against a bounded fictional rate list. If confirmed, batch the existing market relation or label lookup. Preserve displayed values, null fallbacks, pagination and authorization. Profile larger map and candidate lists before proposing a separate change to loading strategy.

**Acceptance.** Repeat measurements on an identified browser and the same fixture. Non-dashboard pages request zero Chart.js bytes and all Dashboard charts still render. Help checks show whether decoded image bytes before scrolling and layout shift change. A fictional 20-row rate-list check shows bounded relation lookups if that repair is made. Record cache state and limitations. No new frontend dependency is required.

## Verification and handoff

The Batch 1 table pass covers overflowing tables in authenticated application lists and details. Cover Markdown-generated Help table regions in Batch 2 so escaping and allowlisting can be verified together. Batch 1 validates field associations in login, tenant registration and staff. Batch 2 applies associations to the changed stall, section, category, rental policy and override forms where a server error key maps to a stable business control. Other forms get the shared focusable summary. Extend linked errors or action names to another screen when the audit identifies a specific barrier. Reports, generic master lists and tenant lists are the initial repeated-action targets.

For Help, use identical manual URL, viewport and cache-disabled runs. Trigger lazy loading if a clearly below-fold allowlisted image is requested before scrolling in two runs. Trigger intrinsic sizing independently if image decode moves visible content or reserves no space and causes a repeatable layout shift. Keep the first visible image appropriately prioritized. Measure before and after with the same methodology.

Start each batch with focused failing tests or a reproducible browser check, then run the affected workflows and automated tests. Use Chrome at 375, 768, 1024 and 1440 CSS px and check changed non-table content at 320 CSS px and 200% zoom. Add keyboard-only navigation, drawer focus, responsive table scrolling, validation and console checks. Smoke test Edge if available and record both versions. Add print and representative Help download checks. Check one screen reader workflow and Firefox or Safari if available and mark unavailable coverage explicitly. Verify against WCAG 2.2 AA criteria relevant to the changes. Run the official post-change scan, production asset build and complete disposable regression suite. Review on actual PHP 7.4 or MySQL only in a suitable isolated environment.

For affected workflows, update manual text, replace affected screenshots with fictional captures, revise applicable diagrams and coverage, rebuild PDF/DOCX exports using the existing build procedure and verify authenticated Help routes. Update AGENTS, the frontend evidence set and the four project checkpoint documents. Record the before/after file inventory and tests so work can resume after interruption. Use a protected source snapshot because this folder has no Git repository. Existing private originals must retain their hashes.
